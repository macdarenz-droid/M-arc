# Lite platform facts for WATCH-C4 (research agent, 2026-10-18)

Sources: the OpenHarmony 7.0 SDK (`js/api/@system.*.d.ts`, `js/build-tools/ace-loader`), arkui_ace_engine_lite v3.2-Release (same animation code in v4.0), the OpenHarmony arkui-js-lite docs. The GT 6 runs Huawei's closed fork, so engine lines show what is likely, not what is proven on the watch.

## Animation
- The lite compiler accepts `animation-name`, `-duration`, `-delay`, `-timing-function` (linear, ease-in, ease-out, ease-in-out), `-fill-mode` (none, forwards), `-iteration-count` (a number or `infinite`; the engine caps 1 to 127). No `animation-direction`: a loop jumps back to its start each cycle (`ace-loader/lib/styler/lib/validator.js`; `animation/transition_impl.cpp`).
- Animatable: translateX, translateY, rotate, width, height, background-color, opacity (`components/component.cpp:819-860`). Opacity fades the element's background, image and text together. Scale and border-radius are not animated. One transform per animation. Only images at their original size rotate.
- Only keyframes 0 and 1 are used (`stylemgr/app_style.cpp:319-320`): a 50% frame becomes the end.
- An opacity pulse ran on a GT 6 (hwgt6 app; `2026-10-17-lite-ui-and-budget.md:258`).
- A bound `animation-duration` compiles to a dynamic style; a running animation reads its duration by reference (`transition_impl.h:184`), so the tempo should follow without a restart (device check). Keep `animation-name` static (the doc: keyframes "cannot be dynamically bound").
- **Native leak risk:** each mount of an animated element adds an animation object to a global list that is freed only when the page exits (`component.cpp:214-216, 985-1007, 39-63`), about 150 to 200 B per mount. Mount animated elements once, outside screen branches.
- `image-animator` exists on lite (bound `images`, bindable `duration`, `$refs` start/stop); not seen on a GT 6. `progress type="arc"` runs on the GT 6.

## Images
`<image src="/common/heart.png">` works; images become raw bitmaps (w x h x 4 + 8 B) in the `.bin`, in the native image cache, not the JS heap or the 48 KB page limit (`lib/lite/lite-image2bin.js`; ui_lite `file_img_decoder.cpp:98`). A 40 px PNG is 6,408 B (twice: `.png.bin` and `.bin`).

## @system.brightness
`getValue`/`setValue` (1 to 255), `getMode`/`setMode` (0 manual, 1 auto), no permission listed. On lite wearables `setKeepScreenOn` cannot stop a screen-off caused by the user or the end of the keep-on period. Nothing says whether `setValue` persists after the app exits; OpenHarmony's own module is off on the watch target (`acelite_config.h:242`), so Huawei's closed module runs: assume it changes the system setting until set back.

## Raise, tilt, wake, touch
- Lite sensors: accelerometer and gyroscope need a system-level permission; onBodyState (worn or not) and heart rate (READ_HEALTH_DATA, about every 5 s) do not; proximity, light and orientation have no effect on lite wearables.
- onShow and onHide exist; whether a dark screen calls them on the GT 6 is unknown.
- Taps bubble: a plain `onclick` never consumes, so a root `onclick` fires for taps anywhere, after a child's own handler (ui_lite `pointer_input_device.cpp:132-146`; ace `event_listener.h:118-130`).

## Second page
Only `router.replace` works on lite; the old page is fully torn down (onDestroy, views, animations) before the new page runs; `params` keys are copied onto the new page's data (declare them in `data`). Timers survive a page switch (keep `clearInterval` in onDestroy). The 48 KB limit is per page file; a trivial page compiles to about 2.7 KB. Declare it in `config.json` `js[0].pages` after the start page.

## Vibrator
`mode: 'short' | 'long'` only; a double buzz is two `short` calls about 250 ms apart (device check).

## Measured cost (debug build, base 43,724 B)
Heart image with a bound-duration pulse in the header +391 B; a done screen with two keyframes +736 B; an idle screen branch with onclick +318 B (`link.js` logic not counted).

## Device probes
The heart PNG draws and its pulse follows a duration change; about 300 remounts of an animated element do not crash; onShow/onHide across an arm-down; a root onclick on taps over children; two `short` vibrations feel like two; `router.replace` to a second page and back, with its params; brightness only if used.
